# Oxide-Tech Local Agent OS: System Architecture

This document describes the high-level and detailed architecture of the Oxide-Tech Local Agent OS. The system is designed as a polyglot (Rust/Python) monorepo containing multiple decoupled modules that communicate via a structured API gateway.

---

## 2. Platform Core Layers

### A. The Gateway Layer (Dual Protocol)
The system operates two parallel servers sharing port `8080` to minimize communication latency:
1. **Actix-web (TCP)**: Runs a multi-worker event loop handling JSON requests and WebSocket streams. Employs WebSocket channels (`/ws/compilation` and `/ws/agent-progress`) to stream compiler and AI state transitions to the client.
2. **Quinn (UDP/HTTP3)**: Handles incoming QUIC-packet streams for high-throughput, low-latency requests. It parses incoming HTTP/3 frames and shares identical internal async execution handlers with the Actix endpoints.
3. **Alt-Svc Negotiation**: Every HTTP response generated by the Actix-web server includes the `Alt-Svc: h3=":8080"; ma=86400` header, indicating to supported clients that they can immediately upgrade their connections to HTTP/3 over UDP.

### B. Async Thread Safety & Non-Blocking Design
To maintain a responsive gateway:
- **Zero-Block Guarantees**: All filesystem read/write, directory walking, and AST parsing operations are offloaded from the main event loops. They are wrapped in `tokio::task::spawn_blocking` blocks.
- **WebSocket Safety**: Actix-web WebSocket streams (`actix_ws::MessageStream`) are not `Send` compliant due to inner thread-local reference counting. They are executed on Actix's local thread pool via `actix_web::rt::spawn` rather than standard tokio runtime threads.

### C. Graph Database Layer (SurrealDB v3)
Upgraded to SurrealDB v3, leveraging the type-safe `surrealdb-types` crate:
- **RecordId Migration**: Instead of legacy string-based identifiers, all database keys utilize the formal `RecordId` layout (e.g. `r"project:uuid"`).
- **SurrealValue Derivation**: AST components, component graphs, and compilations implement `SurrealValue` to perform inline query bindings without JSON translation layers.
- **Multi-backend routing**: The client auto-detects `SURREALDB_URL` scheme:
  - `mem://` runs an embedded, volatile in-memory DB for test suites.
  - `ws://` / `wss://` opens a persistent WebSocket pool targeting remote SurrealDB clusters.

### D. Vector Search Layer (Qdrant & Embeddings)
- Uses **Qdrant v1.18.x** for storage.
- Integrates dense vectors (cosine distance, 1536 dimensions) for semantic retrieval, mapping hardware datasheets to exact micro-controllers and pinouts.
- Hybrid sparse/dense search facilitates lexical token matches over component parameters combined with semantic understanding of queries.

### E. Sandbox Engine
- Executes code generators in isolated Docker environments.
- Enforces time limits, CPU pinning, and memory thresholds.
- Captures compiler diagnostics, returning errors directly to the auto-healing verifier loop.

### F. Background Scheduler & RTL Farsi Blog (Rust Iran Community)
- **Daily Ingestion Loop**: Scrapes and indexes 140+ crates, custom URLs, and 12 GitHub repos politely with custom rate limiting.
- **RSS/Atom Parser**: A lightweight parser in the knowledge core extracting titles, links, summaries, and publication dates.
- **LLM Translation & Curation**: Raw articles are curated and translated into Farsi using the thinker model, auto-publishing the results.
- **SurrealDB Storage**: Implements BlogPost schema with Status (draft/published), tags, and UTC timestamps.
- **RTL Templates**: High-performance, premium glassmorphic, responsive server-rendered HTML engine for `/blog` index, tags, posts, and feed.

## 3. Polyglot CAD & ML Services
The Rust core delegates execution to Python scripts utilizing dedicated CLI utilities or internal bridges:
- **KiCad Python API**: Standardized operations to load, edit, and run Design Rule Checks (DRC) on `.kicad_pcb` board layouts.
- **SKiDL Library**: Netlist generation using Python scripts to verify connections and constraints programmatically.
- **Thermal Sim Engine**: Mesh-based simulations calculating heat dissipation across key silicon components.
- **GNN/ML Training**: PyTorch-based Graph Neural Network training pipelines, optimized for dual RTX 3090 setups.
